## 1. What is unclear, unconvincing, overclaimed, or missing

**Judge verdict:** the implementation is stronger than the current presentation. Right now, nema risks reading as a portable learning protocol with WebMCP attached, rather than a product whose central interaction is made possible by WebMCP.

The story asks the judge to absorb the vault, receipts, trust tiers, inference, alignments, seven origins, extension, MCP bridge, mirrored articles, and learning philosophy before it establishes the smallest complete interaction. Reverse that order.

The opening should be:

> nema gives a browser agent a portable answer to one question: what has this learner already proved? A teaching page exposes WebMCP tools, the learner's vault returns only the relevant state after consent, and the page issues a signed receipt when the learner passes a check.

Then add a literal judged path:

> Judge this in ninety seconds. Open the guided demo, ask the first course to teach you using what you already know, approve one origin-bound request, and pass the check. Then open the second course and ask what to learn next. The page shows the WebMCP tools invoked, the fields released by the vault, and the signed receipt that changed the recommendation.

The most important editorial corrections are:

* Replace universal language such as "the web becomes one course" with the narrower claim that independent teaching pages can reuse learner-owned evidence.
* Replace "mastery" or "ability estimation" with "coarse evidence bands" or "learner-state inference".
* State that a signature proves issuer and integrity, not that the assessment was difficult, honest, or educationally valid.
* Explain what the two tags register. Do not leave "two-tag integration" as a magic trick.
* Disclose that the two cooking courses are demo providers built for the submission.
* Clearly attribute the mirrored articles and state whether they are licensed copies or excerpts.
* Put the extension and MCP bridge after the main browser demo. They are execution evidence, not the thesis.

The live URL needs one dominant button, ideally **"Run the 90 second demo"**. A conceptual landing page alone is not enough a few hours before judging.

My provisional judge read, before a video and clearer WebMCP proof, would be approximately:

| Criterion     | Current impression | Main reason                                                             |
| ------------- | -----------------: | ----------------------------------------------------------------------- |
| Use of WebMCP |         6.5 to 7.5 | Substantial implementation, but the story makes it look like transport  |
| Execution     |           8.5 to 9 | Broad deployed system, tests, real browser E2E work                     |
| Impact        |             7 to 8 | Important problem, but educational claims are broader than demonstrated |
| Creativity    |           8.5 to 9 | Learner-owned state plus page-scoped tools is genuinely distinctive     |

This is technically finalist-level material, but not yet winner-ready presentation.

## 2. Where the submission underuses WebMCP

The vault, signatures, concept graph, spacing policy, and recommendations could all be implemented through REST, a browser extension, or an ordinary centralized account. The submission currently spends so much attention on those components that WebMCP can appear to be one adapter among several.

The single highest-value reframing is a **"Why this requires WebMCP"** section near the top:

> WebMCP is the product boundary, not a delivery detail. On a teaching page, lesson and assessment tools exist only while that page is open; in the vault, learner state remains under the learner's control. The browser agent composes those capabilities at the moment they are needed and asks for consent before learner state is released. Without WebMCP, nema would need a central account, a provider-specific integration, or an extension that scrapes the page.

Back that paragraph with a visible four-step trace:

```text
course.example registered describe_lesson
course.example requested learner readiness
vault.example released 3 scoped status values
course.example issued and signed receipt rcp_...
```

That trace will raise the WebMCP score more than adding another tool. It lets the judge directly observe registration, agent invocation, cross-origin authorization, and a state-changing result.

The one-tag or two-tag provider install is also a stronger WebMCP creativity story than the submission currently gives it credit for. The compelling point is not merely that integration is short. It is that an ordinary page becomes semantically operable by an agent at runtime, using tools derived from what that page teaches.

Do not foreground the Claude Code or Codex bridge. It demonstrates protocol portability, but it also tells the judge that nema works without WebMCP. Use it near the end as evidence that the vault interface is not coupled to one browser runtime.

The tool count should be stated as **unique definitions**, not simultaneous availability. The provider embed registers tools on teaching surfaces; the vault registers its own set on the vault surface. A judge can reasonably challenge a headline total if the browser never exposes all of them in one context.

The most dangerous nontechnical claim is licensing. If either real article has been copied in full without an explicit compatible licence or permission, replace it with a short attributed excerpt before recording. "For demonstration" and "educational use" do not resolve that problem.

The most dangerous technical wording is "verified learning". What is verified is that an issuer signed a particular result. Assessment quality remains a trust-policy question.

## 4. Impact and creativity

Use these two sentences:

> The web has no portable memory of what a learner has already proved, so every course starts from zero and every agent has to guess. nema makes learning state a learner-owned browser capability: a WebMCP-aware page can request the minimum relevant context, adapt one lesson, and return a verifiable receipt without becoming the owner of the learner's full history.

That is stronger than "turn the web into one course" or "learn faster across the web". Those formulations sound universal, depend on unvalidated educational claims, and make nema resemble a general learning dashboard.

The creative contribution is not adaptive learning by itself. It is the separation of roles:

* A teaching page knows what it teaches.
* A learner-controlled vault knows what evidence exists.
* A browser agent composes the two.
* Neither teaching provider needs to own the complete learner profile.

That is a credible new browser primitive. It also connects directly to the challenge rather than to generic edtech.

## 5. Learner model review

The model should be presented as **transparent heuristic learner-state inference**. It should not be presented as psychometrics, a calibrated mastery model, or a validated estimate of general ability.

The central reasoning concerns are:

1. **Scores from different providers are not comparable.** A score of 0.8 on an easy self-authored check and 0.8 on a difficult independent assessment should not have the same meaning. Issuer trust does not calibrate assessment difficulty.

2. **Trust and educational quality are separate.** A registered issuer may be authentic and still produce weak assessments. Cryptographic validity should be a gate, not a positive learning weight by itself.

3. **Fixed thresholds produce false precision.** Band edges, decay rates, trust multipliers, evidence weights, and review intervals are policy defaults. The text should not imply they were estimated from learning data.

4. **The vault may observe selected successes rather than all attempts.** When receipts are issued only after passing, failures and abandoned attempts disappear from the model. That makes "complete learning record" and strong ability claims untenable.

5. **Repeated evidence may be correlated.** Retaking one assessment, receiving several receipts for one event, or using cloned providers can inflate a band unless the system tracks assessment lineage and deduplicates attempts.

6. **Recency is not an individual memory model.** A fixed decay rule is a scheduling heuristic. It does not estimate a learner's forgetting curve unless it is fitted from repeated retrieval outcomes.

7. **Ability aggregation is the weakest semantic claim.** Combining concept evidence under a taxonomy produces an ability summary under that taxonomy. It does not produce a general ability estimate.

8. **Alignment can duplicate evidence.** One receipt must not automatically count through several aliases or one-to-many mappings. Alignment changes should be reversible and trigger deterministic recomputation.

9. **"What to learn next" depends on untrusted curriculum metadata.** Prerequisites, concept granularity, and difficulty can all be manipulated by a provider. The output is a ranked policy recommendation, not an optimal curriculum.

10. **Bands need evidence strength.** Two learners can occupy the same band with one recent receipt or ten consistent receipts. Return evidence count, issuer diversity, age, and conflict status alongside the label.

The scientifically defensible replacement is:

> The vault uses an inspectable policy, not a psychometric model. It discounts old evidence, applies issuer caps, maps the result into coarse bands, schedules reviews, and ranks prerequisite-compatible concepts. The constants are documented demo defaults that can be replaced as better evidence becomes available.

Do not spend the remaining hours inventing a Bayesian layer or tuning constants. Narrowing the claim is faster and more credible.

## 6. Security and privacy review

A careful security judge will separate integrity, truth, authorization, and privacy. The submission should do the same.

**Replay and transfer:** a valid signature does not stop the same receipt being imported multiple times or transferred to another learner. Use a stable signed receipt identifier and make import idempotent. Deduplicate by payload identity, not by the signature bytes.

**Audience binding:** decide whether receipts are portable between a learner's vaults or bound to one audience. An `aud` field has no security value unless verification compares it against an expected audience. A pairwise learner subject may be preferable to one global identifier because it reduces cross-provider correlation.

**Time checks:** reject receipts issued implausibly far in the future, enforce expiry where present, and define permitted clock skew. Otherwise an issuer can manipulate recency and review scheduling.

**Origin keys:** `.well-known` establishes current origin control, not historical key ownership. Include a `kid`, define rotation, retain historical verification keys or pin the key at first import, and provide a revocation story.

**Self-certified Sybil attacks:** a per-issuer cap is not enough when an attacker can generate many issuers. Cap the aggregate contribution of the self-certified tier, or stop that tier from advancing global ability summaries.

**Alignment attacks:** show the definitions on both sides, the issuers, direction, and evidence that would move. A learner approving a vague agent suggestion is not meaningful informed consent. Never auto-confirm alignments.

**Consent lifetime:** origin plus thirty minutes is a useful start, but a grant should also be bound to the requested tool, released fields, purpose, top-level document session, and nonce. All scripts on one origin share that origin, including compromised scripts.

**Prompt injection through WebMCP:** tool descriptions, page content, and tool results are untrusted inputs to the browser agent. A malicious teaching page can try to induce calls to broader vault tools. The trusted vault UI must remain the final authorization boundary.

**Disclosure to the model:** once state is returned to an agent, cryptography cannot make the model forget it. Claim scoped release and data minimization, not that data never leaves the learner, unless the runtime gives that exact guarantee.

**MCP bridge:** Claude Code and Codex do not have browser-origin semantics. Give the bridge a distinct client identity, scopes, expiry, and explicit authorization. Do not imply that the browser consent modal automatically protects the local MCP interface.

**Extension broker:** validate message source and origin, avoid wildcard `postMessage` targets, rate-limit automatic collection, verify receipts before importing, and make every automatic import visible and reversible.

**Registered tier governance:** "registered" is an administrative policy decision. Explain who controls the registry, how issuers enter it, how compromise is handled, and whether prior receipts are downgraded after removal.

Five negative tests would provide more confidence than another page of threat-model prose:

```text
same receipt imported twice        -> rejected or unchanged
receipt for another audience       -> rejected
receipt issued far in the future   -> rejected
unknown token algorithm/version    -> rejected
expired consent from same origin   -> rejected
```
